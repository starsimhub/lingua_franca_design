# EMULSION quickstart, in Starsim

The translation of [examples/emulsion/quickstart](../../../examples/emulsion/quickstart), EMULSION's own showcase: 100 animals, each with an age group, a gestation cycle, and a health state, with births, abortions, maternal protection, vertical transmission, and a seasonal quarantine with a capacity. The model is `model.py`; `compare.py` checks it against the original's reference results.

## Comparison

| Measure | Original | Starsim | |
|---|---|---|---|
| Lines of model code | 280 | 75 | 66 lines, nine of them over 100 characters, so counted twice; docstrings and comments are not counted. About 80 of the original's lines are descriptions, names, and colors. The first version, before `where=` and comparisons in rates, was 76 |

| Results, with EMULSION's quarantine | | | **Agree.** With the quarantine period moved to the steps EMULSION applies it on (`compare.py` does this by `pars=`), every count is within 1.4 animals at every step; `I` within 0.9 and `Q` within 0.5. Starsim ends with about 1.1 fewer animals (64.8 against 65.9), about two standard errors |

Measured on 14 October 2026 with Starsim 4.0.0 (the `v4` branch) on a 20-core x86-64 Linux machine. Row `k` of the analyzer in `compare.py` is compared with EMULSION's row `k`: both are the state after `k` steps (row 0 is the start). The revision for the fixes below gave the same numbers to the last digit, since the same random draws are made.

## What was declared and what was not

Declared: the three state machines, as three modules on the same agents (`growth`, `life`, `health`), run in EMULSION's order of processes; every rate; the fixed stays in `G` (240 days) and `Q` (30 days), with the deaths and abortions competing with them; the force of infection, and the quarantine's room (`Q.n < 20`) in the rate of detection; who each conditional transition applies to (`where=`: adults for `J` to `A` and for conception, infectious mothers for abortion); the deaths, which remove the animal from every module; the quarantine period, as a time series of dates; the initial conditions and ages; and the weekly step in days.

Not declared (each marked as a workaround in `model.py`):

- **Minimum stays (`duration`)**: a function, `stay()`, that switches a rate on once an agent has been in a state for the minimum stay (`E` to `I`, `M` to `S`, `NG` to `G`), or off then (EMULSION's `escape`: the deaths from `M` and `E`)
- **"As soon as"**: `J` to `A` happens on the first step an animal is old enough, written as a rate of 10⁹ a day with `where=`
- **A condition on another module's state**: `where=` is given as a function (`lambda sim: sim.diseases.growth.A`), since the state itself raises an error (finding 2)
- **Actions on crossing a transition**: a subclass of `ss.Disease` whose `step_state()` makes a newborn for each farrowing (placing it in `J`, `NG`, and `I` or `M` itself), counts each animal's abortions, and reports their sum over the living
- **The animals' time of entry at the start**, set to the step before the first
- **The counts in `compare.py`** are taken by an analyzer at the end of each step, since the newborns of the workaround are made after `growth` and `life` have recorded their counts, so would be counted a step late

## Findings

1. **No minimum stay. Still open.** EMULSION's `duration` is a guard: nobody leaves the state by any other transition until it is over, and an `escape` transition is allowed only until then. In Starsim a dwell time is itself the way out, so the first version split each state in two (`E1` for the minimum stay, then `E2` with the rate), which costs a step, since an agent can move only once a step: the epidemic, the births, and the age structure all came a week late, and `J` was 33 against 16 on step 53. The spec has no form for it. Suggested: a `min=` (or `after=`) on a state or transition, so that `ss.Transition(E, I, rate=0.3, after=ss.days(10))` and an `escape` as `before=`, using the `ti_<state>` that agents already have; in a compartmental run, a sub-state of fixed length. This blocks agreement without the workaround.
2. **No condition on a transition. Fixed:** `where=` on `ss.Transition` (and `ss.transmission`, `ss.progression`), a modifier that sets the rate to 0 for everyone else; `J` to `A` is now `where=ppl.age >= adult_age/365`, and conception and abortion use it too. Two things remain. "As soon as" still needs a very high rate. And a declared state of another module as the condition raises an error, so the vignette passes a function instead. Repro: `J, A = ss.states('J A'); growth = ss.Disease(maturity=J >> A @ ss.perday(0.1)); X, Y = ss.states('X Y'); other = ss.Disease(move=ss.Transition(X, Y, rate=ss.perday(1.0), where=growth.A)); ss.Sim([growth, other], n_agents=1000, unit='day', dt=1, stop=10, solver='abm').run()` raises `TypeError: 'State' object is not callable` in `sim.py` (`where=A` the same); `where=lambda sim: sim.diseases.growth.A` works, as does `ss.conditions.Cond('state', 'growth', 'A')`. Suggested: turn a declared state given as `where=` into its lazy condition, as `ss.modify` does. Also new: any `where=` on a transition warns that `modify`'s `Module.link_timepars` was required but not called (repro: `X, Y = ss.states('X Y'); mod = ss.Disease(move=ss.Transition(X, Y, rate=ss.perday(1.0), where=lambda sim: sim.diseases.mod.X)); ss.Sim(mod, n_agents=100, unit='day', dt=1, stop=5, solver='abm').run()`); the results are unaffected.
3. **No births on crossing a transition. Still open.** EMULSION's `produce_offspring` makes one newborn per farrowing, of a prototype chosen by the mother's state. `ss.birth` is an inflow at a rate, drawn as a Poisson number, so cannot give exactly one per farrowing; the workaround grows the people and sets each module's state by hand, using `engine.events` and `people.grow()`. Suggested: an `offspring=` on a transition, or a public form of `add_people()` for a custom step. Needed for agreement.
4. **Counts in a rate were read while agents were moving. Fixed:** as agents, the counts in rates are those at the start of the step for every transition. The repro (`S, I, R` against `I, S, R`, `infection = S >> I @ 0.5*I.n/(S + I + R).n`, `recovery = I >> R @ 1.0`, 5,000 in each of `S` and `I`) now gives 1,041 and 1,097 infections in the first step, where `I, S, R` gave 624 before (about 1,106 expected, so both are within the noise of one draw). The vignette declared `S` first, so its results did not change.
5. **A module's counts missed deaths made later in the step. Fixed:** people who die in one module now leave the other modules' states and are taken out of that step's counts (`growth.n_J + n_A` now equals `n_alive`). The newborns made by the workaround for finding 3 still appear in `growth` and `life` a step late, because they are made after those modules have recorded their counts, so `compare.py` still counts the states itself.
6. **The start is the same as the first step. Still open.** Agents start with `ti_<state> = 0`, the same as those who move during the first step, so a stay from the start lasts a step longer than the same stay entered later; in EMULSION (and most frameworks) the initial state is before the first step. The workaround sets `ti_NG` to −1. Related to the half-step known issue. Suggested: record the initial state as a row of the results and give the initial agents entry time −1 (or the start minus `dt`). Blocks agreement without the workaround (conceptions a week late).
7. **The quarantine period differs by EMULSION's rounding.** EMULSION turns April 1 into whole steps by rounding down (step 12, March 26) and applies the condition at the end of the step, so detection starts on what Starsim calls the step of March 19; its year is 52 steps. The vignette keeps the dates as written, so differs by up to 6.5 animals in `Q` early in each period; with the window as EMULSION applies it, it agrees. Not a Starsim problem.
8. **Smaller things.** Fixed: a comparison in a rate (`Q.n < 20` is 1 or 0, so the quarantine's room is declared); `stop=ss.days(735)` with a start date is the length of the run; `ss.People(age_data=ss.uniform(...))` works; a rate of exactly 0 works; the `W102 LargeStep` note as agents uses the mean dwell time, not the rate of the Erlang stages. Still: `ss.death('M | S | R ->', rate=ss.perday(0.002))` raises `E204 UnknownState: no state named "M | S | R" ... did you mean S, I, R, M?` (repro: `S, I, R, M = ss.states('S I R M'); ss.Disease(infection=S >> I @ 0.1*I.n/(S + I + R + M).n, deaths=ss.death('M | S | R ->', rate=ss.perday(0.002)), loss=M >> S @ 0.1)`), so the vignette uses `(S | R) >> ss.null`. Functions in rates have to use `sim.diseases.health`, not the variable `health`, since the sim works on copies of the modules. `use_aging=True` has to be given for agents to age. `adult_age` is given twice in the original YAML; the second value (30 days) is used, as EMULSION does.
